Signal Twin · control surface spec

Twinctl

The API surface that lets an always-on agent keep a traffic digital twin honest and use it as a world model: observe, fork, perturb, retime, run, compare — plus the verbs a pure simulator never needs: calibrate, validate, and drift, because a twin answers to a real street. Adapted from the simctl harness in murphy-agent; implemented and exercised against the State Street corridor twin.

00What's different about a traffic twin

simctl drives simulators where the sim is the world — OpenTTD, a wafer fab. A traffic twin has a third party in the room: the actual corridor, streaming controller events all day. That splits the surface into three planes with different trust levels and different write rules:

READ-ONLY

Field

The real street, seen through its data exhaust (ATSPM counts, splits, phase events, probe speeds). The agent can pull it, baseline it, and watch it. It can never write to it.

CALIBRATED STATE

Twin

The one world per corridor that is supposed to match reality. Mutated only by calibrate and field re-pulls. Carries a validation score with a freshness date.

DISPOSABLE

Scenarios

Forks of the twin. Shocked, retimed, run at 100× real time, compared, then purged. Anything goes here — that is the point of having a twin.

The prime safety rail: no verb writes to field equipment. The terminal verb is promote, which emits a recommendation package for a human traffic engineer. The loop closes through people, on purpose.

01Verb reference

BUILT exists in ~/repo/signal-twin/twinctl and ran today. SPEC is designed but not yet implemented. Every verb takes --json; text output is one fact per line, sized for a small model's context.

Field — the reality interface

VerbWhat it does
field pull <corridor> --window WSPEC Fetch counts, splits, and phase-termination events from the agency feed (UDOT ATSPM v5 report API today) into field/. Idempotent per window.
field status <corridor>SPEC Data freshness and detector health per signal — which movements are countable, which detectors have gone dark since the twin was built.
field baseline <corridor> <metric>SPEC What is normal: mean/std/percentiles of a field metric over the stored history (split failures per hour, approach volume, arrivals on green).

Twin lifecycle

VerbWhat it does
worldsBUILTList worlds with lineage, calibration state, GEH score.
init <name> --from <assets>BUILTCreate the base twin from built assets (network, reconstructed timing, field demand). The full auto-build from a signal list + bbox is the spec'd v2.
observe <world>BUILTOne-screen summary: window, entry demand, validation score, last run KPIs.
demand <world> · plan <world>BUILTInspect demand (with measured/partial/estimated provenance per approach) and the signal plan (cycle, offsets, greens).
calibrate <world> --iters N --target-pct PBUILTIterative demand fitting: route → run → measure sim movement counts → damped proportional adjustment of turn weights and entry flows against measured field counts. Stops at target or N. Ends with a multi-seed validation.
validate <world>BUILTGEH scorecard, sim vs field, on truly measured movements only. Stamps the world with score + date. Pass = GEH<5 on ≥85%.
drift <corridor>SPECCompare fresh field pulls against the twin's stamped behavior: volume z-scores vs lineage baseline, split-failure spikes, timing-plan changes (a re-timed controller shows up as shifted force-off times). Output: a recalibration recommendation with reasons.

Scenario machinery

VerbWhat it does
fork <src> <new>BUILTClone a world (state, plan, routes, lineage). Cheap, disposable.
retime <world> --offsets J --split-shift JBUILTEdit the signal plan by UDOT signal id: shift offsets; move seconds between mainline and cross green. Refuses edits that leave a green below 8 s.
perturb <world> <shock> [args]BUILTInject a shock: demand_surge (scale an entry or all), lane_closure (cap a lane to walking speed), detector_dark (drift drill). Spec'd: event_egress, signal_flash, transit_priority.
route <world> · run <world> --seeds a,b,cBUILTRebuild routes from demand; simulate 2 h across seeds in parallel; KPIs (mean delay, stops, total delay, arrivals) with across-seed sd.
measure · compare --baseline WBUILTMovement counts from a run; KPI table with deltas against a named baseline.
experiment <world> --candidates JSON --seeds …BUILTThe loop as one deterministic verb (below).
promote <world>BUILTRecommendation package: timing sheet (was → recommended per signal), simulated KPIs with seeds, validation stamp, and the reminder that a human applies it.
kill <world> [--purge]BUILTRemove a scenario. Only --purge deletes files; the base twin refuses.

Always-on

VerbWhat it does
watch <corridor> [--notify]SPECDaemon: pull field data on a schedule, evaluate alert rules, write metrics/events/alerts to the store. --notify wakes the agent by webhook — with a settle window so a burst is one wake (straight from simctl).
alerts [--ack] · events <world> · historyBUILTSPECPer-world audit log is built (every route/run/retime/perturb/calibrate is journaled). The cross-world alert store and ack flow are spec'd.

02experiment — the informed version of a textbook test

Orchestration is where models fumble, so it is one verb, and it upgrades the naive experiments three ways: every candidate is validated before anything forks (all problems reported at once, with the valid choices), every clone runs the same multi-seed set, and the verdict requires the improvement to clear seed noise (|Δ| > 2·sd), because on a well-timed corridor most textbook ideas lose and the difference between −1% and noise is the whole product.

twinctl experiment ss-cal --seeds 42,7,99 --candidates '[
  {"name":"offsets",   "retime": {"offsets": {"7149": -12, "7151": -12}}},
  {"name":"sbgreen",   "retime": {"split_shift": {"7642": 6, "7151": 6}}},
  {"name":"surge-i80", "perturb": {"shock": "demand_surge", "entry": "wb_7148", "pct": 30}}
]'

It forks ss-cal-none plus one clone per candidate, applies each change, runs all clones × all seeds in parallel, and prints the ranked table with significance stars and the exact promote line for the winner. Before any of that, a freshness gate: if the world's validation is missing or failing, the verdict is prefixed with a warning to trust deltas, not absolutes.

03The loops an agent runs

Recalibration loop (cron, or a drift alert)

twinctl field pull state-street --window yesterday-pm   # new reality
twinctl drift state-street                              # anything move? (spec)
twinctl fork ss-base ss-cand
twinctl calibrate ss-cand --iters 6 --target-pct 90
twinctl validate ss-cand                                # multi-seed scorecard
# score improved → ss-cand becomes the new base; else keep old, raise alert

Optimization loop (weekly, or after recalibration)

twinctl experiment ss-base --seeds 42,7,99 --candidates "$(agent proposes from plan+scorecard)"
twinctl promote ss-base-offsets        # → recommendation.md for the engineer

Incident loop (a planned closure lands on the calendar)

twinctl fork ss-base ss-closure
twinctl perturb ss-closure lane_closure --edge 346397922#1
twinctl experiment ss-closure --seeds 42,7,99 --candidates '[mitigations…]'

04Design rules carried over from murphy-agent

  • Terse text, one fact per line; --json everywhere. Output is sized for a small local model's context, so the always-on agent can be cheap.
  • Validate before you fork. A malformed candidate list reports every problem at once with valid choices beside it — one retry, not five.
  • Worlds are directories with lineage. State you can ls, diff, and archive; events.jsonl journals every mutation.
  • Orchestration is deterministic code, not model improvisation. The experiment and calibrate loops are verbs.
  • Wake, don't poll. Alerts settle and debounce into single webhook wakes; the wake message names the agent's first command.

And two rules simctl doesn't need: calibration state is load-bearing (every experiment verdict carries the validation stamp it ran under), and the terminal verb is a document, not an actuation.

05Schemas

worlds/<name>/
  meta.json        lineage, window, validation stamp, calibration record, last run
  net.net.xml      SUMO network (OSM-derived)
  model.json       reconstructed timing + raw measured field demand (the truth to match)
  demand.json      current working demand   ← the only thing calibrate mutates
  plan.tll.xml     current signal plan      ← the only thing retime mutates
  turns.xml flows.xml routes.rou.xml        derived (route)
  field/           raw agency pulls
  runs/<label>-s<seed>/                    tripinfo, vehroutes
  events.jsonl     audit log

demand.json  = { entries: { flow_id: {edge, vph, anchor: [signal, direction]} },
                 signals: { sig: { Direction: {moves: {L,T,R}, source} } } }
candidate    = { name, retime?: {offsets?, split_shift?}, perturb?: {shock, …} }

06Appendix — the surface in use (today's session)

The calibration ask (#2) run entirely through this surface, against real UDOT field counts from Wed Sep 9 2026, 4–6 PM:

$ twinctl init ss-base --from assets && twinctl route ss-base && twinctl run ss-base
ss-base created · 16721 vehicles routed
arrived: 14414   mean_delay_s: 216.0   mean_stops: 3.83     # bit-for-bit = published artifact baseline

$ twinctl validate ss-base                                   # BEFORE calibration
7149 Ea T  field   712  sim   312  GEH 17.70  <-- FAIL
7151 So T  field  1462  sim   838  GEH 18.42  <-- FAIL
7642 So T  field  1488  sim   927  GEH 16.14  <-- FAIL       # southbound starving, 1700S EB starving
GEH<5 on 82.5% of 40 measured movements (mean 3.17, max 18.42) -> NOT PASSING

$ twinctl calibrate ss-base --iters 6 --target-pct 90
iter 0: GEH<5 82.5%  mean 3.17  max 18.42
iter 1: GEH<5 85.0%  mean 2.65  max 16.40
iter 2: GEH<5 87.5%  mean 2.75  max 15.38
iter 3: GEH<5 82.5%  mean 2.64  max 14.85
iter 4: GEH<5 85.0%  mean 2.61  max 17.25
iter 5: GEH<5 85.0%  mean 2.52  max 15.24
calibrated: GEH<5 85.0%  mean 2.43  (PASS)                   # 3-seed validation

$ twinctl validate ss-base                                   # AFTER: what's left fails structurally
7149 Ea T  field   712  sim   376  GEH 14.42  <-- FAIL       # entry pushed to clamp (2135 vph), edge can't inject it
7151 So T  field  1462  sim   900  GEH 16.36  <-- FAIL       # sb_main at clamp (2972 vph), SB pipe caps out
7642 So T  field  1488  sim  1059  GEH 12.03  <-- FAIL
GEH<5 on 85.0% of 40 measured movements (mean 2.43, max 16.36) -> PASS

Reading it: the loop repaired every error that demand scaling can repair — mean GEH fell 23% (3.17 → 2.43) and the southbound gap closed by ~130 veh/h — and it drove the two suspect entries to their safety clamps without closing the rest. That residual is the finding: the six failures cluster on two structural defects of the v0 network, a southbound feed that cannot physically carry 1,488 veh/h (insertion capacity at the north end plus mid-corridor bleed through estimated turn ratios at 1300 S), and a 1700 S eastbound entry the bounding box cut too short to inject 712 veh/h through. Calibration only touches measured movements by design, so it cannot silently hide network errors as demand errors — the next verbs are network fixes (extend the bbox, add a second SB source lane), then re-calibrate. That separation — demand errors converge, structure errors surface — is what makes the loop safe to run unattended.
